Faith 이미지팩 로더 v1.0.0

목표
- 생성형 백엔드 모드(auto/custom)에서는 원본 이미지팩 스크립트 로딩을 건너뛰고, 서버 생성 이미지 경로는 유지합니다.
- 기존 그림 모드(off)에서는 원본 이미지팩 로더를 그대로 사용합니다.
- 원본 이미지팩 카탈로그나 localStorage를 삭제하지 않습니다. 생성형 모드에서는 원본 로더의 결과를 비워 이미지팩이 현재 이미지 목록에 합쳐지지 않게 합니다.
- 이 모드 게이트와 별개로, 아래 폴더/ZIP 가져오기 UI는 원본 wfPackScanFolder 함수에 의존합니다. 현재 대상 HTML에서 해당 함수가 확인되지 않았으므로 외부 pack.js 가져오기는 아직 검증되지 않았습니다.

설치
1. 이 폴더를 wml/mods/faith-image-loader/ 에 둡니다.
2. WML에서 faith-image-loader 모드를 활성화합니다.
3. 게임을 새로고침하고 WML 버튼 줄의 “Faith 이미지팩”을 엽니다.

사용 — 권장 경로
1. “image-packs 폴더 선택 (단계 처리)”를 누릅니다.
2. 게임 HTML 옆에 있는 image-packs 최상위 폴더를 선택합니다.
3. 모드는 디렉터리를 순회하되 이름이 images인 하위 폴더는 건너뛰고 pack.js만 읽습니다. 이미지 파일 내용은 열지 않습니다.
4. 등록이 끝나면 모드 창의 ‘등록된 이미지팩’ 목록에 팩 이름이 세로 목록으로 표시됩니다. 모드 창을 닫았다 다시 열어도 목록은 유지됩니다.\n5. 등록 후 시작화면에 남아 있는 ‘그림이 준비되지 않았습니다’ 경고는 등록된 팩이 확인되면 숨깁니다. 실제 초상화와 장면 그림이 표시되는지도 확인하세요.

호환용 선택
- 브라우저에서 showDirectoryPicker를 지원하지 않을 때만 “호환용 폴더 선택”을 사용합니다.
- 반드시 image-packs 최상위 폴더를 선택하세요. faith-elena 같은 캐릭터 폴더나 base 폴더를 선택하면 안 됩니다.
- 이 방식은 브라우저가 폴더의 파일 목록을 먼저 만들기 때문에 파일이 아주 많은 기기에서는 목록 생성에 시간이 걸릴 수 있습니다. 가능하면 단계 처리 버튼을 사용하세요.

왜 이 방식인가
- 원본 코드의 wfPackScanFolder는 파일의 webkitRelativePath에서 image-packs/ 경로를 확인하고 pack.js만 읽습니다.
- 각 pack.js는 원본 wfPackValidate를 거치고, 원본 설정 저장소의 wfImagePacks 목록과 원본 이미지팩 카탈로그를 갱신합니다.
- 팩 메타데이터에는 image-packs/<팩>/base/pack.js 같은 경로가 보존됩니다. 이미지 파일을 별도 모드 색인에 복제하지 않습니다.
- 등록된 팩은 원본 로더의 경로 생성과 캐시/설정 흐름을 사용합니다. 새 이미지팩을 추가할 때마다 모드 코드를 수정할 필요가 없습니다.

안전장치 및 한계
- 실행 중인 게임에서 원본 wfPackScanFolder 함수를 찾지 못하면 파일을 읽거나 등록하지 않고 오류를 표시합니다. 다른 게임 HTML에 잘못 적용하지 않기 위한 동작입니다.
- image-packs 폴더가 게임 HTML 옆에 있어야 원본의 상대 경로 image-packs/.../images/...가 실제 파일에 연결됩니다.
- 폴더 이름은 정확히 image-packs여야 합니다. 루트가 아닌 폴더를 고르면 등록 전에 거부합니다.
- 단계 처리 방식은 File System Access API를 지원하는 보안 컨텍스트에서 동작합니다. file:// 또는 일반 HTTP 환경에서 지원되지 않으면 호환용 선택을 사용할 수 있지만, 아주 큰 FileList를 만드는 과정은 브라우저 자체의 제약을 받습니다.
- 정적 JavaScript 구문 검사는 APK 폴더 선택기 우회 수정본에서 통과했습니다. Android APK/WebView에서는 기기별 파일 선택기 지원 차이가 있으므로 자동 호환용 선택기 전환과 실제 등록을 실기기에서 확인하세요. Android WebView가 디렉터리 선택 자체를 제공하지 않으면 파일 목록에 `webkitRelativePath`가 포함되지 않을 수 있어, 이 경우 파일 선택기만으로는 폴더 구조를 복원할 수 없습니다. 해당 환경에서는 앱의 파일 접근 권한/폴더 선택 브리지가 추가로 필요합니다. 경고 숨김, 목록 유지, 이미지 출력도 실기기 확인이 필요합니다. 목록 이름은 등록할 때 선택한 image-packs 아래의 최상위 팩 폴더 이름을 사용합니다.


생성형 이미지 설정과의 공존
- 원본 HTML의 실제 상태 저장소는 `window.At.getState().imageBackendMode`이며, 저장 키는 `tavern-settings`입니다. `auto/custom`은 생성 백엔드 모드, `off`는 기존 이미지 전용 모드입니다.
- `auto/custom`에서는 원본 이미지팩 로더 `WOe`가 반환하는 팩 목록을 비워 원본 매니페스트 `Wb`에 네이티브 이미지팩이 합쳐지지 않게 합니다. 별도 서버 이미지팩을 가져오는 `JOe` 경로는 변경하지 않습니다.
- `off`에서는 원본 `WOe` 함수를 그대로 호출합니다. 전환 시 원본 캐시를 무효화해 다음 조회부터 모드에 맞는 목록을 사용하게 합니다.
- 이 처리는 `window.__WAYWARD_IMAGE_PACKS__`나 저장 데이터를 삭제하지 않습니다. `auto/custom`은 생성 백엔드가 실제 연결됐는지와 무관하게 설정된 모드만으로 판단합니다. 기본 설정은 `auto`이므로 네이티브 이미지팩만 사용하려면 설정에서 `off`를 선택하세요.
- 폴더/ZIP 가져오기 UI는 별도 기능이며 원본 `wfPackScanFolder`를 요구합니다. 현재 대상 HTML에서 해당 심볼을 찾지 못했으므로, 외부 `pack.js` 등록은 실기기 테스트 이전에 실제 등록 경로를 다시 구현해야 합니다.
- 모드 전환과 이미지 출력은 정적 검사 및 모의 테스트까지만 확인했습니다. Android APK/WebView와 실제 생성 백엔드 연결 상태에서의 실기기 검증은 아직 하지 않았습니다.


ZIP 이미지팩 등록
- 모드 창의 “ZIP 이미지팩 불러오기” 버튼으로 올바른 구조의 ZIP 파일을 선택할 수 있습니다.
- ZIP 내부 경로는 `image-packs/<팩 이름>/.../pack.js` 형식이어야 합니다. ZIP 최상위에 압축용 래퍼 폴더가 하나 더 있어도 그 안의 `image-packs/`부터 상대 경로를 맞춥니다.
- ZIP 내부를 훑되 실제로 추출·등록하는 파일은 `pack.js`뿐입니다. 대량의 이미지 파일은 압축 해제하지 않습니다.
- 일반 ZIP의 Store(무압축)와 Deflate 압축을 지원합니다. 암호화 ZIP, 분할 ZIP, ZIP64는 지원하지 않습니다. Deflate 해제에는 브라우저의 `DecompressionStream('deflate-raw')` 지원이 필요합니다.
- ZIP 가져오기는 코드 구문 검사를 통과했으며, 실제 이미지팩 ZIP 파일을 이용한 Android APK/브라우저 실기기 등록 검증은 별도로 필요합니다.
