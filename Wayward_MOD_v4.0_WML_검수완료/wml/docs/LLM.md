# LLM 이야기 기반 (`llm-core`) 설명서

게임 원문은 그대로 두고, LLM으로 짧은 대사·속마음·몸짓을 **더하는** 부모 모드예요.

- **기본 기능:** 아내나 손님이 말한 줄 바로 뒤에, 그때 아내의 기분·감정·성격에 맞는 반응을 한 줄 붙여요.
- **자식 모드:** `llm-core`를 바탕으로 새 상황(밤 대화, 손님 잡담, 사건…)을 만들어 따로 배포할 수 있어요. 예제는 `llm-night-talk`(밤 대화)예요.
- **원문은 건드리지 않아요.** LLM 줄은 원래 줄 바로 뒤(같은 시각)에 들어가고, 앞에 `✧`가 붙어요(설정에서 끌 수 있어요). 색은 게임의 이야기 색 규칙을 그대로 따라요.
- **실패해도 게임은 그대로예요.** LLM이 없거나, 느리거나, 이상한 글을 내면 아무 줄도 더하지 않아요.

## 1. LLM 준비하기

### 사양별 추천 모델 (2026년 10월 기준)

4비트(Q4) GGUF 기준 크기예요. 대화 길이에 따라 1~3GB가 더 들어요.

| 사양 | 추천 | 메모 |
|---|---|---|
| 그래픽카드 없음·약함 | 클라우드 키, 또는 이 모드를 끔 | 끄면 원래 게임 그대로예요 |
| 8GB + 램 32GB | Gemma 4 26B-A4B, Qwen3.6-35B-A3B | MoE 모델이에요. 한 번에 일부(3~4B)만 계산해서, 무거운 부분을 램에 두고도 돌아요. llama.cpp는 `--cpu-moe` 옵션을 써요 |
| 12~16GB | Gemma 4 12B (약 7GB), Qwen3.5-9B (약 6GB) | 그래픽카드에 통째로 올라가서 빨라요 |
| 24GB 이상 | Qwen3.8-27B (약 17GB), Gemma 4 31B (약 19GB) | 품질이 가장 좋아요 |

- 한국어 품질은 실제 게임 문장으로 몇 번 돌려 보고 고르는 게 제일 빨라요. Qwen 계열은 한자가 섞이는지 보세요. 섞인 줄은 이 모드가 알아서 버려요.
- 회사에서 낸 공식 모델은 성인 장면에서 거절할 수 있어요. 거절하면 그 줄만 안 붙고 게임은 그대로예요. 거절을 없앤 커뮤니티판(abliterated)을 쓰는 사람도 있지만 문장 품질이 조금 떨어지기도 해요.
- **생각 모드는 꺼요.** 설정의 "생각 모드 끄기"가 기본으로 켜져 있어요(Qwen 계열). Gemma 4는 따로 켜지 않으면 생각하지 않아요.

### 프로그램별 주소

| 프로그램 | 주소 | 메모 |
|---|---|---|
| llama.cpp `llama-server` | `http://127.0.0.1:8080/v1` | 예: `llama-server -m 모델.gguf -c 8192 --port 8080` |
| LM Studio | `http://127.0.0.1:1234/v1` | 개발자 탭에서 서버를 켜고, 서버 설정에서 CORS를 켜요 |
| Ollama | `http://127.0.0.1:11434/v1` | 환경 변수 `OLLAMA_ORIGINS=*`가 필요해요. 모델 칸에는 `ollama list`에 나오는 이름을 써요 |
| KoboldCpp | `http://127.0.0.1:5001/v1` | |
| vLLM | `http://127.0.0.1:8000/v1` | |
| 클라우드 (OpenRouter 등) | `https://openrouter.ai/api/v1` | API 키가 필요해요. 성인 내용을 허용하는지는 업체·모델 정책을 확인하세요 |

- 다른 컴퓨터에서 LLM을 돌리면 그 컴퓨터의 주소를 넣어요. SSH로 잇는다면 `ssh -N -L 8080:127.0.0.1:8080 사용자@그컴퓨터`로 터널을 열고 `http://127.0.0.1:8080/v1`을 쓰면 돼요.
- 게임 파일을 더블클릭해서 열면(`file://`) 브라우저가 다른 주소로 요청할 때 **CORS 허용**을 확인해요. 연결 시험이 "연결 안 됨"이면 거의 이 문제예요.

## 2. 연결하기

1. 모드 관리자에서 **LLM 이야기 기반**을 켜고 새로고침해요.
2. 왼쪽 아래 **🗨** 버튼을 눌러요.
3. "프로그램 고르기…"에서 쓰는 프로그램을 골라요. 주소가 채워져요.
4. 모델 칸은 비워 두면 서버의 첫 모델을 써요. "모델 목록"으로 골라도 돼요.
5. **연결 시험**을 눌러 "된다!"가 나오면 끝이에요.

창 아래 **최근 요청**에서 LLM에 보낸 글과 받은 글을 그대로 볼 수 있어요. 결과가 이상하면 여기부터 보세요.

## 3. 설정

| 설정 | 뜻 |
|---|---|
| 잠시 멈추기 | LLM에 아무것도 보내지 않아요 |
| API 키 | 클라우드용. 이 브라우저에만 저장되고 "옮기기·백업" 파일에는 들어가지 않아요 |
| 생각 모드 끄기 | Qwen 계열에 `enable_thinking: false`를 보내요. 서버가 모르는 칸이라고 하면 알아서 빼고 다시 보내요 |
| JSON 모드 요청 | 지원하는 서버에서 답을 JSON으로 받게 해요. 꺼도 이 모드가 답에서 JSON을 찾아 읽어요 |
| 대사 뒤 반응 · 확률 · 최소 간격 | 기본 기능을 켜고 끄고, 얼마나 자주 붙일지 정해요. 간격은 게임 분이에요 |
| ✧ 표시 | LLM이 쓴 줄 앞에 붙는 표시 |
| 하루 요청 상한 | 게임 하루에 보내는 요청 수의 상한 (클라우드 비용 대비) |
| 온도 · 기다리는 시간 · 동시 요청 수 | 다양함, 시간 초과, 한 번에 보낼 요청 수 |
| 말투 지시 | 모든 요청에 붙는 지시. 예: "대사는 짧게. 아내는 남편에게 존댓말." |
| 상황 목록 | 자식 모드가 더한 상황까지 하나씩 켜고 꺼요 |

세 번 연달아 실패하면 1분 쉬었다가 다시 해요. 쉬는 동안에는 게임 상태를 건드리지 않아요.

## 4. 자식 모드 만들기

`requires`에 `llm-core`를 넣고 `api.use('llm-core')`로 부모 기능을 받아요. 연결, 상황 읽기, 검사, 세이브 저장, 표시는 부모가 다 해요. 자식은 **언제, 무엇을**만 정해요.

```js
WML.define({
  id: 'llm-night-talk',
  name: '밤 대화 (LLM)',
  version: '0.1.0',
  game: '>=2026-10-04',
  requires: ['llm-core'],
  setup(api) {
    const llm = api.use('llm-core');
    llm.situation({
      id: 'llm-night-talk/bedtime',               // 다른 모드와 겹치지 않게 <모드id>/<이름>
      name: '밤 대화',
      on: ['phase', 'action'],                    // 언제 볼지 (아래 "사건" 표)
      when: (ctx, ev) => ev && (ev.to === 'bedroom' || ev.type === 'go_to_bedroom'),
      oncePerDay: true,
      chance: 0.6,
      lines: [1, 2],                              // 1~2줄
      ask: ctx => '하루 영업이 끝나고 침실이다. 아내가 오늘 있었던 일을 떠올리며 당신에게 한두 마디 건넨다.',
      effects: { mood: [-2, 3] },                 // LLM이 고를 수 있는 효과와 범위
      fallback: null,                             // LLM이 없을 때 쓸 문장들 (없으면 아무것도 안 함)
    });
  },
});
```

부모가 LLM에 보내는 글은 이렇게 생겼어요. `ask`는 `[할 일]` 칸에 들어가요.

```
[때·곳] 1일째 20:07 · 밤 · 침실 · 아내 위치: 침실 · 날씨: 흐림
[아내] 마라 · 기분 59/100(보통) · 흥분 21/100(조금 달아오름) · 기력 56/100(보통) · 취기: 없음 · 남편 신뢰 51/100
[성격] 침착함, 속내를 잘 숨김, 성욕이 적음
[감정] 특별한 감정 없음
[손님] 없음
[가게] 돈 50골드 · 악명 0 · 명성 11
[최근 이야기]
- (이야기 창의 마지막 8줄)

[할 일] (ask)
출력 형식(JSON 하나): {"lines":[{"text":"…","tone":"kind"}],"effect":{…}} …
```

### 상황 칸 (`llm.situation({...})`)

| 칸 | 뜻 |
|---|---|
| `id` | 필수. `<모드id>/<이름>` |
| `name` | 🗨 창의 상황 목록에 보이는 이름 |
| `on` | 필수. 사건 이름 하나나 배열 (아래 표) |
| `when(ctx, ev, state)` | 더 따질 조건. `false`면 이번엔 안 해요 |
| `chance` | 0~1 확률 (함수도 돼요) |
| `cooldown` | 다시 하기까지 기다릴 게임 분 (함수도 돼요) |
| `oncePerDay` | 게임 하루에 한 번만 |
| `ask(ctx, ev)` | LLM에게 시킬 일 (글자나 함수) |
| `lines` | 줄 수. `2` 또는 `[1, 2]` |
| `effects` | LLM이 고를 수 있는 효과. `{ mood: [-2, 3], arousal: [0, 5], energy: [-3, 0], feelings: ['tenderness', 'shame'], feelingMax: 20 }` |
| `fallback` | LLM이 없거나 답이 검사에 떨어질 때 쓸 문장 배열 (함수도 돼요). 하나를 골라 써요 |
| `tone` | `fallback` 문장의 색 (`kind`, `thought`, `flirt` …) |
| `priority` | 대기열 순서. 높을수록 먼저 (기본 반응은 0, 기본값 1) |
| `maxAge` | 이 게임 분이 지나도록 답이 없으면 버려요 (기본 90) |
| `anchor(ev, state)` | 답을 붙일 이야기 줄. 주면 그 줄 바로 뒤에 들어가요 |
| `check(text, ctx)` | 줄마다 더 검사. `false`면 버려요 |
| `after(lines, effect)` | 줄이 들어간 뒤에 불려요 |

### 사건 (`on`)

| 이름 | 언제 | `ev` |
|---|---|---|
| `lines` | 행동 하나가 끝나고 새 이야기 줄이 생겼을 때 | `{ lines: [이야기 줄…] }` |
| `action` | 게임 행동 뒤 | `{ type, action, owner }` |
| `phase` | 영업 단계가 바뀔 때 | `{ from, to }` (`prep`·`service`·`last_call`·`closed`·`bedroom`) |
| `newDay` | 날이 바뀔 때 | `{ day, from }` |
| `patronEnter` · `patronLeave` | 손님이 들어오고 나갈 때 | `{ patron }` |
| `reset` | 다른 게임이나 예전 세이브를 불러왔을 때 | `{ state }` |

### 상황 읽기 (`ctx`)

`llm.context()`가 돌려주는 값이에요. `when`과 `ask`에서 받아요.

| 칸 | 뜻 |
|---|---|
| `day`, `time`, `phase`, `phaseName`, `room`, `roomName`, `weather` | 때와 곳 |
| `wife.name`, `mood`, `arousal`, `energy` | 0~100 수치 |
| `wife.drunk`, `drunkName`, `trust`, `annoyance` | 취기, 남편 신뢰, 남편에게 짜증 |
| `wife.traits` | 성격 낱말 (`침착함`, `성에 보수적` …) |
| `wife.feelings` | 강한 감정 4개까지 `[{ emotion, name, intensity, strength, about }]` |
| `patrons` | 지금 손님 `[{ id, name, type, kind, intent, chemistry, voice }]` (`voice`는 한글판의 말투 단계) |
| `gold`, `reputation` | 돈, 악명·명성 |
| `recent` | 이야기 창의 마지막 8줄 (조사 표기를 화면처럼 푼 글) |

## 5. API 전체

`const llm = api.use('llm-core')`

| 이름 | 뜻 |
|---|---|
| `llm.situation(def)` | 상황 등록. 돌려받은 함수를 부르면 등록이 풀려요 |
| `llm.generate({ prompt, system, json, maxTokens, temperature, priority, label, stale })` | 요청 하나 → `Promise<{ text, data }>`. `json: true`면 `data`에 읽은 JSON. 대기열에서 밀려나면 `null` |
| `llm.context(state?)` / `llm.describe(ctx)` | 상황 읽기 / 그걸 프롬프트 글로 |
| `llm.lines(out)` | 답에서 줄 꺼내기 `[{ text, tone }]` |
| `llm.check(text)` | 한 줄이 검사를 통과하는지 |
| `llm.addLines(lines, at)` | 지금 이야기 창에 줄 넣기. `at: { slot, coLocated, source }` |
| `llm.on(event, fn)` | 사건 받기 (위 표). 돌려받은 함수로 그만 받아요 |
| `llm.ready()`, `llm.status()`, `llm.settings()` | 연결 준비, 대기열 상태, 지금 설정 |
| `llm.emotionName(id)` | 감정 id → 화면 이름 (`shame` → `수치심`) |

부모 모드가 쓰는 WML 기능 (0.6.1):

- `api.provide(obj)` / `api.use(id)`: 모드끼리 기능 주고받기 ([SDK.md](SDK.md))
- `api.secret.get()` / `api.secret.set(value)`: "옮기기·백업" 파일에 들어가지 않는 값 (API 키)

## 6. 안전망과 규칙

LLM 답은 이 순서로 걸러요. 떨어지면 `fallback`, 그것도 없으면 아무것도 안 붙여요.

1. JSON에서 줄을 꺼내요. 머리말·번호·`✧`는 떼요.
2. 길이(2~240자), 한글판이면 한글이 있는지와 한자가 섞였는지를 봐요.
3. 미성년을 가리키는 낱말이 있으면 버려요.
4. 최근 이야기와 똑같은 문장은 버려요.
5. 상황의 `check`를 거쳐요.
6. 효과는 상황이 정한 범위로 잘라서 넣어요. 수치는 0~100을 넘지 않아요.

자식 모드를 만들 때 지킬 것:

- 원문 줄을 고치거나 지우지 말고, 줄을 **더하기만** 하세요.
- 효과는 좁게 주세요. LLM이 게임 균형을 정하게 하면 안 돼요.
- 등장인물은 모두 성인이에요. 부모의 기본 지시에도 들어 있지만, `ask`에서도 어기지 마세요.
- 같은 사건에 여러 상황이 걸리면 대기열이 길어져요. `chance`·`cooldown`·`oncePerDay`로 줄이세요.
